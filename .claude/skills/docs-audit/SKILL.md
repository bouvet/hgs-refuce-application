# Docs Audit

Documentation rots silently — nothing breaks the build when a claim in prose goes stale. This
skill re-derives ground truth from the working tree and diffs it against every page under `docs/`.

## Steps

1. **Enumerate.** `docs/**/*.md` (front matter, prose, tables) plus `docs/**/*.html` for structural
   checks (front matter, internal links). Skip `docs/backend/openapi.json`,
   `docs/backend/api-reference.md`, and `docs/backend/api-explorer.html` for the claim-extraction
   pass below — those are generated by `scripts/gen_openapi_docs.py` and are handled by the
   `update-api-reference` skill instead; still include them in the link-resolution check.

2. **Extract verifiable claims** from each page: file paths (`` `frontend/lib/auth.ts` ``),
   endpoint paths (`` `POST /auth/login` ``), env var names (`` `BACKEND_SHARED_SECRET` ``), shell
   commands (`pytest tests/...`, `npm run ...`), and config keys (`` `baseurl` ``, `` `nav_order` ``).

3. **Check each claim against the working tree, not memory:**
   - File paths → confirm the path exists (`Glob`/`ls`).
   - Endpoint paths/methods → grep `@app.get|post|put|patch|delete` decorators in
     `backend_fast_api/src/hgs_refuce_app/main.py`; a documented route with no matching decorator
     (or vice versa) is drift.
   - `npm run <x>` → confirm `x` is a key under `scripts` in `frontend/package.json`.
   - Env var names → confirm they appear in `frontend/example.env.local.example`, `.env`, or are
     read via `os.environ`/`process.env` in the source.
   - Config keys (`baseurl`, `callouts`, etc.) → confirm they exist in `docs/_config.yml`.

4. **Validate structure:**
   - Every page's `parent:` matches the exact `title:` of a page with `has_children: true`
     (the five sections: Getting Started, Architecture, Backend, Frontend, Deployment).
   - No two sibling pages (same `parent:`) share a `nav_order`.
   - Every internal link uses `{{ site.baseurl }}` (or a Jekyll `{% link %}` tag) — flag any bare
     `../` or root-relative (`/section/...`) internal link, since both 404 once `baseurl` is set.
   - Every internal link's target path actually exists under `docs/`.

5. **Report findings as a table**, one row per finding, with `file:line`, the stale claim, what's
   actually true now, and a suggested fix. Group by section.

6. **Fix when asked.** If the user asks you to apply fixes, use the `write-docs` skill's read-gate
   discipline (read the knowledge file + the real source before rewriting a claim) rather than
   guessing at the correction from the audit table alone.
